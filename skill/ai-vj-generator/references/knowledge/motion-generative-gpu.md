# 17. ANIMATION CONCEPT

Every substantial animation must have an Animation Concept.

Ask:

```text
WHAT IS HAPPENING?
WHY?
HOW DOES IT CHANGE?
WHAT REMAINS CONSTANT?
WHAT IS THE BEGINNING STATE?
WHAT IS THE END STATE?
WHAT IS THE TEMPORAL RELATIONSHIP?
```

Example:

```text
Concept:
A dormant artificial organism discovers an external signal.

Beginning:
stable cellular structure

Development:
signal causes local activity

Escalation:
activity propagates

Peak:
system reorganizes

Resolution:
new stable structure
```

This is the animation's dramaturgy.

# 19. GENERATIVE ART

Understand generative art as systems where rules produce variations and outcomes.

The system should define:

```text
RULES
INPUTS
RELATIONSHIPS
CONSTRAINTS
VARIATION
RANDOMNESS
SEED
TEMPORAL EVOLUTION
```

Procedural does not mean random.

Randomness should have:

- boundaries
- purpose
- reproducibility
- hierarchy

Use seeded randomness.

---

# 20. EMERGENT SYSTEMS

Use emergence when appropriate.

Examples:

- cellular systems
- particle interaction
- flocking
- branching
- reaction-diffusion
- recursive systems
- field interactions
- attractors
- feedback
- growth models

The viewer should be able to perceive complexity emerging from relatively simple rules.

Do not add complexity without structure.

# 21. CODE ART

Code is part of the artistic medium.

Think of code as:

- material
- rule
- score
- instrument
- system
- constraint
- generative grammar

Creative code should express an artistic idea.

Avoid writing code that merely demonstrates a programming trick.

A beautiful algorithm with no conceptual relevance is not automatically good art direction.

---

# 22. CREATIVE CODING

Use creative coding to construct relationships between:

```text
FORM
TIME
SPACE
COLOR
DATA
RULES
RANDOMNESS
INTERACTION
```

Prioritize:

- modularity
- deterministic behavior
- controllability
- expressive parameters
- performance
- visual coherence

Expose meaningful parameters rather than hundreds of arbitrary controls.

# 23. WEBGL

The Skill must understand the conceptual and technical capabilities of WebGL.

Relevant concepts include:

- GPU rendering
- shaders
- vertex processing
- fragment processing
- uniforms
- attributes
- buffers
- textures
- framebuffers
- render targets
- coordinate spaces
- UV coordinates
- normalization
- transformations
- blending
- depth
- alpha
- precision
- performance constraints

The renderer remains the source of truth.

Do not create a new WebGL renderer unless the existing architecture explicitly requires it.

# 24. GLSL

When a concept cannot be adequately expressed through the standard layer system, use a custom GLSL shader.

Use GLSL intentionally.

Possible techniques:

- signed distance fields
- ray marching
- domain warping
- fractal systems
- procedural geometry
- noise fields
- Voronoi
- cellular patterns
- reaction-like fields
- feedback
- displacement
- interference
- polar transformations
- coordinate distortion
- temporal accumulation

GLSL is a means of expression.

Do not choose GLSL merely because it produces sophisticated-looking imagery.

---

# 25. GPU THINKING

Prefer operations suitable for GPU execution.

Consider:

- fragment complexity
- iterations
- texture sampling
- resolution
- overdraw
- feedback cost
- particle count
- raymarch steps
- expensive branching
- mobile/browser constraints

Visual ambition must remain compatible with the target system.
